# 策略绩效分析体系：收益率、最大回撤、夏普、Sortino与Calmar

- **这一篇文章讲绩效分析。策略复盘如果只说“最后赚了多少”，其实是不够专业的。因为收益背后还有波动、回撤、胜率、盈亏比、交易次数和风险暴露。**

- **我希望这个模块能把策略从“结果导向”拉回到“过程分析”：不仅看最终权益，也看它是怎样涨上去、怎样回撤、每一笔交易质量如何。**

## 1. 为什么不能只看最终收益

很多初学者做策略回测时，最关注最终收益率。但单看最终收益是远远不够的。一个策略可能最终赚了钱，但中间经历过巨大回撤；也可能收益很高，但波动极大，实盘中很难坚持。

因此，一个策略是否值得继续研究，至少要从收益、风险、稳定性和交易质量几个角度综合评估。

在这个加密货币量化框架中，绩效分析模块主要基于两类数据：

1. `equity_curve`：权益曲线；
2. `trades`：成交记录。

权益曲线用于分析账户整体表现，成交记录用于分析交易行为。

## 2. 权益曲线是绩效分析的基础

回测引擎每处理完一根 K 线，都会记录当前账户权益：

```text
(datetime, equity)
```

这些点连起来就是权益曲线。大部分绩效指标都可以从权益曲线中计算出来，例如：

- 总收益率；
- 年化收益率；
- 波动率；
- 最大回撤；
- 夏普比率；
- Sortino 比率；
- Calmar 比率。

权益曲线的意义在于，它不只告诉我们最终赚了多少，还告诉我们赚钱的过程是否平滑、是否经历过剧烈亏损。

## 3. 总收益率和年化收益率

总收益率比较直观：

```text
total_return = final_equity / initial_equity - 1
```

但不同回测周期之间不能只比较总收益。一个策略 1 个月赚 10% 和 3 年赚 10%，含义完全不同。因此需要年化收益率，把不同时间长度的结果转换到同一尺度。

年化收益率可以帮助我们比较不同回测区间的策略表现，但它也有局限：如果回测时间太短，年化结果可能会被严重放大。

## 4. 最大回撤

最大回撤是我认为最重要的风险指标之一。它衡量的是权益曲线从历史高点下跌到低点的最大幅度。

```text
running_peak = 历史最高权益
drawdown = equity / running_peak - 1
max_drawdown = drawdown 的最小值
```

例如，一个策略从 10000 涨到 15000，又跌到 9000，那么这段最大回撤约为：

```text
9000 / 15000 - 1 = -40%
```

最大回撤反映的是策略最痛苦的阶段。对于真实交易来说，很多策略不是因为最终不赚钱，而是因为中途回撤太大，使用者无法坚持。

## 5. 夏普比率

夏普比率用于衡量单位波动带来的超额收益。简化理解为：

```text
Sharpe = 平均收益 / 收益波动率
```

夏普越高，说明策略每承担一单位波动，获得的收益越高。

但夏普也有明显缺点：它把上涨波动和下跌波动都当成风险。现实中，投资者通常更关心下跌波动，而不是上涨波动。

## 6. Sortino 比率

Sortino 比率就是为了改进夏普比率而来的。它只关注下行波动：

```text
Sortino = 平均收益 / 下行波动率
```

如果一个策略上涨时波动很大，但下跌风险可控，那么 Sortino 可能比 Sharpe 更能体现它的真实风险收益特征。

在加密货币市场中，由于价格波动非常剧烈，Sortino 比率可以帮助我们更关注亏损方向的风险。

## 7. Calmar 比率

Calmar 比率通常用年化收益率除以最大回撤：

```text
Calmar = annual_return / abs(max_drawdown)
```

它的直觉非常清晰：为了获得这样的年化收益，策略承受了多大的最大回撤？

如果一个策略年化收益很高，但最大回撤也极大，Calmar 未必好看。这个指标对趋势策略、合约策略和高波动市场尤其有参考价值。

## 8. 成交记录指标

除了权益曲线，成交记录也很重要。通过 `trades` 可以统计：

- 交易次数；
- 胜率；
- 平均盈利；
- 平均亏损；
- 盈亏比；
- profit factor；
- 手续费总额。

这些指标能帮助我们判断策略到底是靠少数几笔大盈利支撑，还是整体交易质量比较稳定。

例如，胜率高不一定代表策略好。如果每次赚得很少，但亏一次亏很多，策略仍然可能长期亏损。反过来，趋势策略胜率可能不高，但如果盈亏比足够好，也可能有研究价值。

## 9. 绩效分析的局限

绩效指标是必要的，但不能迷信。因为所有指标都建立在历史数据和回测假设上。如果数据质量差、手续费滑点低估、策略存在未来函数，那么绩效指标再漂亮也没有意义。

因此，绩效分析应该和以下内容一起看：

1. 数据是否干净；
2. 回测假设是否保守；
3. 参数是否过拟合；
4. 交易次数是否足够；
5. 是否跨周期、跨品种验证；
6. 实盘或模拟盘表现是否一致。

## 10. 总结

一个专业一点的策略复盘，不应该只展示最终收益，而应该至少包含：

- 收益指标；
- 风险指标；
- 回撤指标；
- 波动指标；
- 交易质量指标；
- 图表化复盘。

在这个项目中，绩效分析模块承担的就是这个角色：把回测结果从“账户最后多少钱”，提升为“策略全过程的风险收益画像”。

## 11. 绩效分析源码阅读路线

这一篇主要对应：

```text
crypto_quant/analysis/performance.py
crypto_quant/analysis/bokeh_report.py
```

`performance.py` 负责计算指标，`bokeh_report.py` 负责把指标和回测过程画成图。二者的关系可以理解为：

```text
BacktestResult
  -> PerformanceAnalyzer
  -> 指标字典 / 绩效对象
  -> BokehBacktestReport
  -> HTML 图表报告
```

分析模块不负责回测，也不负责交易，它只消费回测结果。这种边界很清楚。

## 12. 指标之间应该如何搭配看

不同指标回答的问题不同：

| 指标 | 回答的问题 |
| --- | --- |
| 总收益率 | 最终赚了多少 |
| 年化收益率 | 按年化尺度表现如何 |
| 波动率 | 收益过程是否剧烈波动 |
| 最大回撤 | 最痛苦的下跌幅度有多大 |
| Sharpe | 单位总波动带来多少收益 |
| Sortino | 单位下行波动带来多少收益 |
| Calmar | 年化收益相对于最大回撤是否划算 |
| 胜率 | 交易中盈利次数占比 |
| 盈亏比 | 平均赚一次和亏一次的比例 |

一个策略不能只看某一个指标。比如高胜率策略可能亏一次很大；高收益策略可能最大回撤也很大；高 Sharpe 策略可能样本太少。

## 13. 为什么要结合图表看指标

指标是压缩后的结果，图表能还原过程。例如最大回撤告诉我们“跌了多少”，但不告诉我们：

- 回撤发生在哪段行情；
- 回撤持续多久；
- 是连续亏损还是单次暴跌；
- 策略是否在震荡区间频繁交易；
- 买卖点是否集中在错误位置。

所以项目中不仅计算绩效指标，还生成 Bokeh 报告，把权益曲线、回撤曲线、价格走势和交易点结合起来看。

## 14. 教程式复盘一个策略的顺序

以后复盘策略时，可以按这个顺序：

1. 先看权益曲线整体是否平稳；
2. 再看最大回撤和回撤持续时间；
3. 再看收益是否来自少数几笔极端交易；
4. 再看手续费对策略是否有明显侵蚀；
5. 再看买卖点和价格走势是否符合策略逻辑；
6. 最后再考虑是否需要换品种、换周期、做参数稳定性测试。

这比直接看收益率更稳妥。

## 15. 从源码看 PerformanceAnalyzer 的输入和输出

`PerformanceAnalyzer` 的核心入口是 `analyze(equity_curve, trades)`。这说明绩效分析模块并不直接依赖策略对象，也不直接读取数据库，而是只接收两个已经整理好的结果：

```text
equity_curve: list[(datetime, equity)]
trades: list[Trade]
```

这种设计的好处是分析模块可以复用。无论结果来自 CSV 回测、MySQL 回测，还是未来的模拟盘记录，只要能整理成权益曲线和成交列表，就可以使用同一套指标计算逻辑。

`analyze()` 内部大致分成两条线：

```text
权益曲线 -> 收益率序列 -> 总收益 / 年化 / 波动 / 回撤 / Sharpe / Sortino / Calmar
成交记录 -> realized_pnls -> 胜率 / profit factor / 平均盈亏 / 最大单笔盈亏
```

所以这不是简单地打印几个数字，而是把账户层面的表现和交易层面的质量分开统计。

## 16. 收益率序列是很多指标的共同基础

源码中的 `returns()` 会把权益曲线转换成相邻两期之间的收益率：

```text
return_i = equity_i / equity_(i-1) - 1
```

这个序列后续会被多个指标复用：

1. 波动率需要收益率序列的标准差；
2. Sharpe 需要平均收益和收益波动；
3. Sortino 需要平均收益和下行波动；
4. 年化处理需要知道一共有多少期数据。

这里有一个容易忽略的问题：`periods_per_year` 默认是 365。它适合把每个权益点近似理解为日频数据。如果实际回测是 5 分钟 K 线，那么更严谨的做法应该根据 timeframe 调整年化周期，否则年化收益和年化波动会偏离真实尺度。

因此，在教程复盘中，看到年化指标时不能只看数值，还要问：这个年化假设和我的数据周期是否匹配？

## 17. realized_pnls 如何从成交记录里还原单笔盈亏

成交记录不是天然等于“每笔完整交易”。一个策略可能分批开仓、分批平仓，也可能先买后卖、先卖后买。源码中的 `realized_pnls()` 做了一件很重要的事：根据成交方向维护当前持仓均价，并在出现反向成交时计算已实现盈亏。

简化理解如下：

```text
如果当前成交和已有持仓方向一致：
    更新持仓数量
    更新加权平均开仓价
    累加手续费

如果当前成交和已有持仓方向相反：
    计算本次平掉的数量
    根据多空方向计算价差盈亏
    扣除对应手续费
    记录 realized pnl
```

这样做可以把零散的 `Trade` 转换成一组已经闭合的交易盈亏。后面的胜率、平均盈利、平均亏损、profit factor 都依赖这个列表。

这里也能看出为什么成交记录要比订单记录更适合做绩效统计：订单可能未成交、部分成交或取消，而成交记录才是真正影响账户盈亏的事件。

## 18. profit factor 和胜率要一起看

`profit_factor` 的计算方式是：

```text
profit_factor = gross_profit / abs(gross_loss)
```

它回答的问题是：策略总共赚的钱，是总共亏的钱的多少倍。

如果一个策略胜率很高，但 profit factor 很低，说明它可能经常小赚、偶尔大亏。如果一个策略胜率不高，但 profit factor 不错，说明它可能亏损次数多，但盈利交易幅度更大。

所以复盘时可以把胜率和 profit factor 组合起来看：

| 情况 | 可能含义 |
| --- | --- |
| 高胜率 + 高 profit factor | 交易质量较好，但仍需检查样本量 |
| 高胜率 + 低 profit factor | 小赚大亏，风险可能隐藏在尾部 |
| 低胜率 + 高 profit factor | 趋势类策略常见，依赖少数大盈利 |
| 低胜率 + 低 profit factor | 策略逻辑大概率需要重新检查 |

这种分析比单独说“胜率 60%”更有意义。

## 19. PerformanceReport 字段可以怎样理解

项目中用 `PerformanceReport` 保存绩效分析结果。它不是一个随意拼出来的字典，而是把指标按含义固定下来，方便 Bokeh 报告、数据库或后续 dashboard 复用。

| 字段 | 含义 |
| --- | --- |
| `initial_equity` | 初始权益 |
| `final_equity` | 最终权益 |
| `total_return` | 总收益率 |
| `annual_return` | 年化收益率 |
| `volatility` | 年化波动率或收益波动尺度 |
| `max_drawdown` | 最大回撤 |
| `sharpe_ratio` | 夏普比率 |
| `sortino_ratio` | Sortino 比率 |
| `calmar_ratio` | Calmar 比率 |
| `trade_count` | 成交数量 |
| `closed_trade_count` | 已闭合交易数量 |
| `win_rate` | 胜率 |
| `profit_factor` | 总盈利 / 总亏损绝对值 |
| `gross_profit` | 毛盈利 |
| `gross_loss` | 毛亏损 |
| `average_win` | 平均盈利 |
| `average_loss` | 平均亏损 |
| `max_win` | 最大单笔盈利 |
| `max_loss` | 最大单笔亏损 |

固定这些字段的好处是：报告层不用重新理解计算过程，只需要展示结果；后续如果保存到数据库，也能保持字段稳定。

## 20. periods_per_year 为什么不能随便用

`PerformanceAnalyzer` 中有一个参数 `periods_per_year`，它会影响年化收益、年化波动、Sharpe 和 Sortino。

如果权益曲线是日频，可以粗略使用：

```text
periods_per_year = 365
```

但如果回测使用 5 分钟 K 线，理论上每年周期数会大得多。加密货币又是 7x24 小时交易，因此常见估算可以是：

```text
365 * 24 * 12 = 105120
```

因为 1 小时有 12 根 5 分钟 K 线。

这说明年化指标一定要结合数据频率解释。如果周期设置不匹配，年化收益和 Sharpe 可能被放大或缩小。教程复盘时，我更倾向于同时看总收益、最大回撤和原始权益曲线，而不是只看一个年化数字。

## 21. 绩效模块还可以继续扩展什么

当前绩效模块已经能完成基础复盘，但如果要继续提高专业度，还可以补充：

1. 回撤持续时间，而不只是最大回撤幅度；
2. 月度收益热力图，用来观察策略是否只在某些月份有效；
3. 多空分开统计，看收益主要来自做多还是做空；
4. 手续费占毛利润比例，判断高频交易是否被成本侵蚀；
5. 按市场状态分组，例如趋势、震荡、急跌阶段；
6. 参数分组对比，用于观察策略是否对参数过度敏感。

这些扩展都不需要改变策略本身，只需要让回测结果记录得更完整，然后在分析层增加新的统计函数。
