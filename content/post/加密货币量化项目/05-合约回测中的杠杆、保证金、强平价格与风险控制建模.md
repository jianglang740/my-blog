# 合约回测中的杠杆、保证金、强平价格与风险控制建模

- **这一篇文章专门讲合约回测。加密货币市场里合约交易非常常见，但合约不是简单地把收益乘上杠杆，真正麻烦的是保证金、未实现盈亏、强平风险和多空方向管理。**

- **如果一个合约回测不考虑这些机制，那么高杠杆策略很容易被回测结果“美化”。所以我在项目中把现货和合约账户逻辑分开处理，尽量让回测结果更接近真实交易约束。**

---

## 1. 为什么合约回测更复杂

现货回测的账户逻辑相对直观：有多少钱，买多少币，卖出后现金增加。但合约交易引入杠杆、多空、保证金、未实现盈亏和强平机制，账户状态会复杂很多。

如果在合约策略中只简单计算价格涨跌，很容易严重低估风险。例如，一个 10 倍杠杆策略即使方向判断大体正确，也可能因为中途波动过大触发强平。

因此，在这个加密货币量化框架中，我单独为合约模式设计了账户、持仓、保证金和强平判断逻辑。

## 2. 合约账户需要记录什么

合约账户至少需要记录：

| 字段 | 含义 |
| --- | --- |
| cash | 钱包余额或现金余额 |
| equity | 账户权益，通常约等于 cash + 未实现盈亏 |
| available | 可用资金 |
| margin | 已占用保证金 |
| maintenance_margin | 维持保证金 |
| margin_ratio | 保证金风险比例 |
| realized_pnl | 已实现盈亏 |
| unrealized_pnl | 未实现盈亏 |

其中最容易混淆的是 cash 和 equity。cash 更接近钱包余额，equity 会随着持仓浮盈浮亏变化。合约风控更关注 equity，因为强平风险本质上取决于账户权益能不能覆盖维持保证金。

## 3. 杠杆与初始保证金

合约开仓时，名义价值为：

```text
notional = price * amount
```

如果使用 `leverage` 倍杠杆，则初始保证金近似为：

```text
required_margin = notional / leverage
```

例如，账户有 10000 USDT，使用 10 倍杠杆开 30000 USDT 名义价值的仓位，理论上需要约 3000 USDT 保证金。杠杆提高了资金利用率，也放大了价格波动对账户权益的影响。

在框架中，开仓前会检查可用资金是否足够支付保证金和手续费。如果不足，订单会被拒绝。

## 4. 多头与空头的盈亏计算

多头和空头的盈亏方向相反。

多头未实现盈亏可以理解为：

```text
unrealized_pnl = (mark_price - entry_price) * amount
```

空头未实现盈亏可以理解为：

```text
unrealized_pnl = (entry_price - mark_price) * amount
```

因此，持仓对象中不仅要记录数量，还要记录方向。项目中通过 `PositionSide` 区分普通持仓和空头持仓，策略可以使用：

```python
self.short(symbol, amount)
self.cover(symbol, amount)
```

来表达开空和平空。

## 5. 盯市与账户权益更新

每根 K 线推进时，回测引擎会根据当前价格更新持仓的 mark price 和未实现盈亏，这个过程叫盯市。

盯市之后，账户权益会重新计算：

```text
equity = cash + unrealized_pnl
available = equity - margin
```

如果不做盯市，回测过程中账户权益就无法反映市场波动，也无法判断策略是否已经接近强平风险。

## 6. 维持保证金与强平判断

维持保证金可以理解为交易所要求账户至少保留的风险缓冲。项目中使用一个简化的维持保证金率：

```text
maintenance_margin = notional * maintenance_margin_rate
```

当账户权益不足以覆盖维持保证金时，可以认为触发强平风险。

简化逻辑可以表示为：

```text
if equity <= maintenance_margin:
    liquidation triggered
```

真实交易所的强平规则会更复杂，还会涉及阶梯保证金、资金费率、标记价格、保险基金等因素。但在学习型框架中，先建立这个简化模型，有助于理解杠杆风险的本质。

## 7. 为什么强平建模很重要

如果一个合约回测完全不考虑强平，那么高杠杆策略往往会显得异常优秀。因为它只统计最终收益，却忽略了中途是否已经爆仓。

强平建模至少可以帮助我们识别三类问题：

1. 策略仓位过重；
2. 止损设置过宽或失效；
3. 杠杆倍数与波动率不匹配。

对于加密货币市场来说，这一点尤其重要。因为加密市场波动大、极端行情频繁，合约策略如果没有保证金和强平模型，回测结果就很容易失真。

## 8. 项目中的风险控制接口

除了引擎层的保证金和强平逻辑，策略层也可以做主动风控。例如递归 CUSUM 反转策略中，就加入了止盈止损判断：

```text
达到止盈比例 -> 平仓
达到止损比例 -> 平仓
```

此外，策略还可以通过 `position_ratio` 控制每次使用多少可用资金开仓，而不是满仓梭哈。

这说明风控不应该只放在一个地方，而应该分层设计：

| 层次 | 风控内容 |
| --- | --- |
| 策略层 | 仓位比例、止盈止损、信号过滤 |
| 回测引擎层 | 保证金、手续费、滑点、强平 |
| 实盘层 | 下单校验、交易所规则、同步账户状态 |
| 系统层 | 日志、告警、密钥管理、人工兜底 |

## 9. 当前模型的局限

当前合约模型仍然是简化版本，后续可以继续扩展：

1. 加入资金费率；
2. 区分逐仓和全仓；
3. 支持阶梯维持保证金率；
4. 使用标记价格而不是 K 线 close；
5. 模拟部分成交和滑点冲击；
6. 增加最大杠杆和最小保证金约束。

这些都是从学习型框架走向更真实交易系统时需要补充的内容。

## 10. 总结

合约回测的核心不是简单地把收益放大几倍，而是要完整考虑杠杆带来的风险放大。

在这个项目中，我通过账户、持仓、保证金、盯市和强平判断，初步搭建了合约回测的风险模型。它虽然简化，但已经能够帮助我们更真实地理解策略在高波动市场中的风险暴露。

## 11. 合约逻辑对应的源码位置

合约回测主要分散在三个地方：

```text
crypto_quant/config.py                  # BacktestConfig 中的杠杆、保证金参数
crypto_quant/strategy/base.py           # Account、Position、short、cover、close_position
crypto_quant/engine/backtest.py         # _apply_futures_trade、_mark_to_market、_check_liquidation
```

其中 `BacktestConfig` 里和合约相关的字段包括：

```python
leverage: Decimal
margin_mode: MarginMode
maintenance_margin_rate: Decimal
liquidation_fee_rate: Decimal
```

这些字段共同决定合约账户如何开仓、占用保证金、判断强平和处理强平费用。

## 12. 开仓、平仓和反手的区别

合约交易里有三个容易混淆的动作：

| 动作 | 含义 |
| --- | --- |
| 开仓 | 从空仓变成有仓位 |
| 平仓 | 减少已有仓位，直到归零 |
| 反手 | 先平掉原方向，再开相反方向 |

项目中用 `reduce_only` 防止平仓单变成反向开仓。例如平空时使用：

```python
self.cover(symbol, amount)
```

内部会生成买入方向、`position_side=SHORT`、`reduce_only=True` 的订单。这样可以明确表达“这是平空，不是开多”。

## 13. 保证金和权益变化示例

假设账户权益为 10000 USDT，使用 10 倍杠杆，以 2000 USDT 价格开多 1 ETH：

```text
notional = 2000 * 1 = 2000
required_margin = 2000 / 10 = 200
```

开仓后，账户会占用 200 USDT 保证金。之后如果价格涨到 2100，未实现盈亏为：

```text
(2100 - 2000) * 1 = 100
```

账户权益会随未实现盈亏变化。如果价格下跌，未实现亏损也会降低权益。当权益低于维持保证金要求时，就进入强平风险区间。

## 14. 为什么合约策略必须关注路径风险

现货策略通常更关注最终价格涨跌，但合约策略更关注路径。因为即使最终方向判断正确，中间剧烈波动也可能先触发强平。

例如：

```text
开多价格 2000
中途跌到 1700
最后涨到 2300
```

如果没有杠杆，最后可能赚钱；但如果是高杠杆合约，中途跌到 1700 时可能已经爆仓，根本等不到后面的上涨。

这就是为什么合约回测必须建模保证金和强平，而不能只看最终收益。

## 15. 从源码看合约开仓时账户发生了什么

在 `_apply_futures_trade()` 中，如果当前成交是开仓，框架会先计算名义价值和所需保证金：

```text
notional = trade.price * trade.amount
required_margin = notional / leverage
```

然后检查：

```text
available >= required_margin + fee
```

如果可用资金不足，订单会被拒绝。通过检查后，框架会：

1. 更新持仓均价；
2. 增加仓位占用保证金；
3. 增加账户总保证金；
4. 从 cash 中扣除手续费。

这里要注意，合约开仓不是直接把全部名义价值从现金里扣掉，而是占用保证金。杠杆越高，同样名义价值需要的初始保证金越少，但账户承受价格波动的能力也越弱。

## 16. 平仓时为什么要释放保证金

当合约仓位被平掉一部分时，框架会按平仓比例释放保证金：

```text
close_ratio = close_amount / abs(previous_amount)
released_margin = position.margin * close_ratio
```

同时计算已实现盈亏：

```text
多头：pnl = (平仓价 - 开仓价) * 数量 - 手续费
空头：pnl = (开仓价 - 平仓价) * 数量 - 手续费
```

然后：

1. 把 realized_pnl 加到账户；
2. 减少仓位保证金；
3. 减少账户占用保证金；
4. 如果仓位归零，清空 entry_price 和 position.margin。

这一步很关键。因为如果只计算盈亏、不释放保证金，账户可用资金会越来越不准确；如果只释放保证金、不计算盈亏，策略收益又会失真。

## 17. liquidation_price 是怎样近似估算的

项目中还给持仓计算了一个简化强平价格。多头大致是：

```text
entry_price * (1 - 1 / leverage + maintenance_margin_rate)
```

空头大致是：

```text
entry_price * (1 + 1 / leverage - maintenance_margin_rate)
```

这不是交易所的完整强平公式，但能帮助我们理解杠杆风险：

- 杠杆越高，`1 / leverage` 越小，强平价格离开仓价越近；
- 维持保证金率越高，账户需要保留的安全垫越多；
- 多头怕价格下跌，空头怕价格上涨。

在图表或持仓快照中记录强平价格，可以帮助复盘时判断策略是否频繁接近危险区间。

## 18. 盯市是合约风控的基础

每根 K 线中，回测引擎都会调用 `_mark_to_market()` 更新持仓状态。它会根据当前 close 计算：

1. 每个持仓的 mark_price；
2. 每个持仓的 unrealized_pnl；
3. 账户总 unrealized_pnl；
4. maintenance_margin；
5. equity；
6. available；
7. margin_ratio。

对于合约来说，盯市不是可选功能。因为强平判断依赖的是当前账户权益和维持保证金，而不是开仓时的状态。

如果没有盯市，一个策略可能中途已经进入爆仓区间，但回测直到最后才结算，这会严重美化高杠杆策略。

## 19. 强平流程在回测中如何处理

当满足：

```text
equity <= maintenance_margin
```

回测引擎会调用 `_liquidate_all()`，把所有持仓按照当前 close 价格强制平掉，并扣除强平手续费。

之后账户状态会被重置：

1. 持仓数量归零；
2. 持仓保证金归零；
3. 未实现盈亏归零；
4. 账户保证金归零；
5. 账户权益变成剩余 cash；
6. 回测循环结束。

这让回测结果能够体现“路径中已经被淘汰”的情况，而不是只看最终价格是否反弹。

## 20. 合约模型后续最值得补强的部分

当前合约模型已经能帮助理解杠杆风险，但如果继续接近真实交易，还可以补充：

1. 资金费率；
2. 标记价格和最新成交价的区别；
3. 阶梯维持保证金率；
4. 逐仓和全仓的差异；
5. 部分强平；
6. 最大杠杆限制；
7. 交易所最小下单数量和名义价值限制。

这些内容会让合约回测从“风险教学模型”进一步靠近“交易所规则模拟”。
