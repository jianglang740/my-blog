## 1. 模块、包和项目结构的基础概念

- **模块（Module）**：一个 `.py` 文件就是一个模块。
- **包（Package）**：一个包含 `__init__.py` 文件的文件夹。哪怕 `__init__.py` 是空的，这个文件夹也会被 Python 认作“包”，里面的模块就能用点号 `.` 来访问。
- **项目根目录**：通常是你整个项目的顶层文件夹，`main.py` 或 `setup.py` 所在的地方。

假设你的项目结构如下（这就是一个典型的**包结构**）：

```
crypto_quant/                  # 项目根目录
├── main.py                    # 程序入口
├── config/
│   ├── __init__.py
│   ├── settings.py            # 配置常量
│   └── .env                   # 敏感信息
├── data/
│   ├── __init__.py
│   └── fetcher.py
├── strategy/
│   ├── __init__.py
│   └── ma_cross.py
└── utils/
    ├── __init__.py
    └── logger.py
```

每个文件夹里都有 `__init__.py`，这样 `config`、`data`、`strategy`、`utils` 都是合法的 Python 包。

## 2. 如何让一个文件夹里的代码调用另一个文件夹的代码？——导入系统

Python 找模块的依据是 `sys.path`，它是一个列表，里面存放着所有搜索模块的目录。**项目根目录一般需要被加入 `sys.path`**，这样你就可以从根目录出发，用“绝对导入”来调用任何模块。

### 绝对导入（推荐）
在项目任何文件中，直接写完整的包路径：

```python
# strategy/ma_cross.py
from data.fetcher import fetch_ohlcv
from config.settings import TRADING_PAIR
from utils.logger import setup_logger
```

### 怎样确保根目录在 `sys.path` 里？

**最佳实践**：始终从项目根目录运行你的主程序，并且使用模块运行方式：
```bash
cd crypto_quant
python -m main        # 或者 python main.py
```
如果 `main.py` 在根目录下，直接 `python main.py` 运行时，Python 会自动把根目录加入 `sys.path`，这样所有以根目录为起点的 `from config.xxx import ...` 都能正常工作。

如果从别的地方运行，或者想在子文件夹的脚本里也能直接用绝对导入，可以在该脚本**最开头**临时添加：

```python
import sys
import os
# 把项目根目录加到 sys.path
sys.path.append(os.path.dirname(os.path.dirname(os.path.abspath(__file__))))
```
不过这种方法不优雅，还是建议养成“从根目录启动，用绝对导入”的习惯。

### 相对导入
在包内部，可以用一个点 `.` 表示当前包，两个点 `..` 表示上级包。但这种导入**要求**该模块是作为包的一部分被导入的，不能直接运行这个文件。易出错，不如绝对导入清晰，新手可先跳过。

## 3. 数据在模块之间如何传递？——别让脚本“各自跑”

你说“这个程序要用到另一个程序跑出来的数据”，说明你可能是分别运行了 `fetch_data.py` 和 `backtest.py` 两个独立的脚本，然后前者输出一个文件，后者再读这个文件。这种方式固然可以，但在一个项目里更推荐的做法是：**写一个统一的入口（main.py），把所有功能组织成可以调用的函数和类，由主程序按顺序调用**。

示例：

```python
# main.py
from data.fetcher import fetch_ohlcv
from strategy.ma_cross import generate_signals
from backtest.engine import run_backtest

if __name__ == "__main__":
    df = fetch_ohlcv("BTCUSDT", "1h", limit=500)   # 返回 DataFrame
    signals = generate_signals(df)
    result = run_backtest(df, signals)
    print(result)
```

这样，`fetch_ohlcv` 的结果直接作为参数传给下一个函数，内存里就完成了交互，完全不需要中间文件。如果确实需要缓存原始数据，也可以在 `fetch_ohlcv` 里顺便存一个 CSV，这属于函数内部的事情。

## 4. `config.py` 和 `.env` 的区别及正确用法

### `config.py`（或 `settings.py`）
- 是一个**Python 模块**，可以直接定义变量、字典、类等。
- 适合存放**非敏感的、代码化的配置**，例如交易对、均线周期、常量等。
- 使用：直接 `from config.settings import SOME_CONSTANT`。

```python
# config/settings.py
TRADING_PAIR = "BTCUSDT"
TIMEFRAME = "1h"
MA_SHORT = 20
MA_LONG = 50
```

### `.env` 文件
- 是一个纯文本文件，格式为 `KEY=VALUE`，通常用于存放**敏感信息**，如 API 密钥、数据库密码。它**绝不应该**被提交到 Git 仓库。
- 你需要 `python-dotenv` 这个第三方库来加载它，它会把 `.env` 里的键值对注入到系统的环境变量 `os.environ` 中。
- 使用：先 `load_dotenv()`，再用 `os.getenv("KEY")` 读取。

```python
# .env 文件内容
BINANCE_API_KEY=your_api_key_here
BINANCE_SECRET=your_secret_here
```

```python
# config/settings.py 或直接在使用处
from dotenv import load_dotenv
import os

load_dotenv()  # 会自动寻找当前目录下的 .env，也可指定路径

API_KEY = os.getenv("BINANCE_API_KEY")
SECRET = os.getenv("BINANCE_SECRET")
```

**一句话总结**：`config.py` 管程序逻辑常量，`.env` 管秘钥私密信息；两者可以配合使用。

## 5. 路径与目录——不再头疼

### 核心概念
- **当前工作目录（CWD）**：你在终端里运行 Python 时所处的目录。用 `os.getcwd()` 可获得。
- **`__file__`**：当前 Python 文件自身的**路径**（相对或绝对，取决于运行时如何传入）。
- **绝对路径**：从系统根目录（如 `/home/user/...`）开始的完整路径。
- **相对路径**：相对于当前工作目录的路径，如 `./data/btc.csv`。

### 在项目里安全地构建路径
永远不要手动拼接 `/` 或 `\`，要用 `os.path.join()`，或者更现代的 `pathlib`。

**使用 `os.path` 的例子：**

```python
import os

# 获取当前文件所在目录
current_dir = os.path.dirname(os.path.abspath(__file__))
# 假设当前文件是 data/fetcher.py，current_dir 就是 .../crypto_quant/data

# 项目根目录就是上两级
project_root = os.path.dirname(current_dir)

# 构建一个指向 config/.env 的绝对路径
env_path = os.path.join(project_root, 'config', '.env')

# 加载这个指定的 .env 文件
from dotenv import load_dotenv
load_dotenv(env_path)
```

**使用 `pathlib` 的更易读写法（推荐学习）：**

```python
from pathlib import Path
from dotenv import load_dotenv

BASE_DIR = Path(__file__).resolve().parent.parent  # 项目根目录
env_path = BASE_DIR / 'config' / '.env'
load_dotenv(env_path)
```

## 6. 三个库的作用与实战

### `sys` 库
负责与 Python 解释器交互。最重要的是：
- `sys.path`：模块搜索路径列表。
- `sys.argv`：命令行参数。
- `sys.exit()`：退出程序。

在你的问题场景中，**唯一需要它的时候就是临时添加项目根目录到搜索路径**（不推荐作为常规操作）。更好的办法是调整你的运行方式（始终从根目录启动）。

### `os` 库
负责与操作系统交互。对你最有用的是：
- `os.getenv('KEY')`：读取环境变量。
- `os.path.join(...)`：跨平台拼接路径。
- `os.path.dirname(path)` 和 `os.path.abspath(...)`：处理路径。
- `os.makedirs(path, exist_ok=True)`：创建文件夹。

### `dotenv` 库（python-dotenv）
唯一的任务：读取 `.env` 文件，把里面的键值对设为环境变量。核心函数：
- `load_dotenv(dotenv_path)`：加载 `.env`。不传参数时默认从当前工作目录找 `.env`。
- 之后就可以用 `os.getenv` 读取了。

**注意**：`load_dotenv()` 一般在程序最开始调用一次即可，比如放在 `main.py` 或 `config/settings.py` 的顶部。

### `strategy/ma_cross.py`
```python
import pandas as pd
from config.settings import MA_SHORT, MA_LONG

def generate_signals(df: pd.DataFrame):
    """计算双均线交叉信号，返回带有信号列的DataFrame"""
    if df.empty:
        return df
    df['ma_short'] = df['close'].rolling(MA_SHORT).mean()
    df['ma_long'] = df['close'].rolling(MA_LONG).mean()
    df['signal'] = 0
    df.loc[df['ma_short'] > df['ma_long'], 'signal'] = 1
    df.loc[df['ma_short'] <= df['ma_long'], 'signal'] = -1
    return df
```

### `utils/logger.py`
```python
import logging
import sys

def setup_logger(name):
    logger = logging.getLogger(name)
    logger.setLevel(logging.INFO)
    handler = logging.StreamHandler(sys.stdout)
    formatter = logging.Formatter('%(asctime)s - %(name)s - %(levelname)s - %(message)s')
    handler.setFormatter(formatter)
    logger.addHandler(handler)
    return logger
```

### `main.py`（入口）
```python
from data.fetcher import fetch_ohlcv
from strategy.ma_cross import generate_signals
from utils.logger import setup_logger

logger = setup_logger(__name__)

def main():
    logger.info("Starting crypto quant...")
    # 1. 获取数据
    df = fetch_ohlcv()
    # 2. 生成信号
    signals_df = generate_signals(df)
    # 3. 后续可以接入回测或实盘模块
    logger.info("Signals generated, ready for backtesting.")
    print(signals_df.head())

if __name__ == "__main__":
    main()
```

### 如何运行
在终端确保位于 `crypto_quant` 目录下：
```bash
python main.py
```

一切导入都将顺利，因为当前工作目录就是项目根目录，Python 能找到 `config`、`data` 等包。

## 8. 常见问题与解决

| 问题 | 原因 | 解决 |
|------|------|------|
| `ModuleNotFoundError: No module named 'config'` | 项目根目录不在 `sys.path` 中 | 在根目录用 `python main.py` 运行，或用 `python -m main` |
| 直接运行子文件夹里的脚本报错 | 相对路径混乱，工作目录不对 | 不要直接运行子模块脚本，始终通过主入口调用 |
| `.env` 读出来是 `None` | `load_dotenv()` 找不到文件，或路径写错 | 使用 `load_dotenv(绝对路径)`，并打印检查 |

## 9. 你的“框架感”到底是什么？

就是**将代码合理地分散到不同模块和包中，每个模块只做一件事，通过清晰的接口（函数、类）互相调用，配置文件独立管理**。这种工程化的思维，就是所谓的项目架构。

现在你已经理解了：
- **分文件夹加 `__init__.py`** → 包
- **通过绝对导入相互调用** → 清晰的依赖关系
- **`config.py` + `.env` 配合** → 配置与秘钥分离
- **`os`、`pathlib` 处理路径** → 代码可移植
- **`sys`、工作目录、运行方式** → 导入成功的关键
